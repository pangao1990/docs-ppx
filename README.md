# PPX 文档站

本仓库是 PPX 的中文介绍和开发文档，使用 VitePress 1.6。默认首页和导航介绍最新版，V5 原有文档保留原路径，并通过“版本 → V5（归档版本）”访问。

## 本地开发

需要 Node.js 22.13+ 和 pnpm 11.x，与 PPX 源码仓库保持一致。

```bash
pnpm install --frozen-lockfile
pnpm dev
```

访问终端显示的 `/docs-ppx/` 地址。生产构建与链接检查：

```bash
pnpm check
pnpm preview
```

构建产物位于 `dist/`。`base` 为 `/docs-ppx/`，部署到其他子路径时必须同步调整 `.vitepress/config.js` 的 `base` 和 favicon 地址。

## 内容归属

| 路径 | 内容 |
| --- | --- |
| `src/index.md` | 最新版首页 |
| `src/v6/guide/` | 从上手到发布的教程 |
| `src/v6/reference/` | CLI、配置、Python、JavaScript 和 RPC 参考 |
| `src/v6/internals/` | 架构、生命周期、安全边界和贡献指南 |
| `src/v5/index.md` | V5 归档导航及版本说明 |
| `src/v5/home.md` | 原 V5 首页，保留历史内容 |
| `src/guide/`、`src/api/` | 原 V5 页面，保持原 URL |
| `.vitepress/theme/LegacyBanner.vue` | V5 版本提示和 V6 返回入口 |

新增当前文档页面后，在 `.vitepress/config.js` 中补充导航，并为读者提供前置知识、可运行示例、期望结果和下一步链接。接口签名、默认值和错误码需要对照 PPX 源码，不能把待实现功能写成已支持。

## 版本标注规则

品牌、首页、导航、侧栏和常规教程默认介绍最新版，使用“PPX”“指南”“API”等名称，不反复添加主版本号。只有版本菜单、V5 归档提示及两代版本的差异说明需要明确标注 V5/V6。

保留已有 `/v6/` 文档路径以兼容外部链接；URL 中的版本目录不要求出现在显示标题中。安装命令中的精确包版本、项目格式、兼容契约和示例文件名仍按真实实现书写，不能为了隐藏版本标识而改错技术参数。修改标题时应保留已有锚点的兼容入口。

## 保留 V5 的规则

不要用 V6 内容覆盖 `src/guide/` 和 `src/api/`，也不要删除这些页面后仅用重定向代替。外部博客和旧项目仍依赖旧链接。归档页面上的统一提示由主题注入，不需要重写每篇旧正文。

V5 原首页已经保存为 `src/v5/home.md`。其中历史功能描述属于 V5，不能作为 V6 的能力承诺。V5 的 API 目录在所有归档侧栏中可达。

## 验证与部署

`pnpm check` 构建全站并检查产物中的站内页面、资源和锚点链接，同时确认 V5 必要入口存在。提交前还应在浏览器检查首页、V5 切换、搜索、深色主题和窄屏导航。

GitHub Actions 在推送 `main` 或手动触发时执行检查，然后部署 GitHub Pages。本地修改和构建不会自动提交或发布。PPX 框架的跨平台测试和安装包验证在应用源码仓库进行。
